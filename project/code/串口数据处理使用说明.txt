data_handle文件负责的是串口数据处理

以下是使用说明：
4月10日第一版
这一版已经实现了地图获取与小车位置获取包括小车坐标和车头朝向角度
但是区别于学长的串口数据处理
学长的串口数据处理已经和算法，控制模块结合到一起了
我这里提供的是只负责数据处理的底层
怎么应用就看你们了。基本的状态量，标志位都有

函数说明：
uart_blob_init();初始化并清空地图小车状态
process_blob_data();数据处理用户层面函数在主循环里调用
uart_send_map_request和uart_send_car_request发送获取地图/小车位置请求

关键数据：
地图数据在char map_data[MAP_ROWS][MAP_COLS] = {{0}};
小车在extern CarPose car_pose;
类型是一个结构体
typedef struct {
    int32 x_raw;
    int32 y_raw;
    int32 yaw_raw;
    float x;
    float y;
    float yaw;
} CarPose;

状态标志位：
1、bool uart_data_processing_enabled;
处理总开关。初始化后默认会被置为 true。
如果你手动改成 false，process_blob_data() 就不会继续解析。
2、bool map_data_ready;
是否至少成功收到过一帧地图。
第一次成功解析地图后会变成 true，之后不会自动清零。
3、bool map_data_updated;
是否刚收到一帧新地图。
常见用法：应用层检测到它为 true 后读取 map_data，处理完手动清成 false。
4、bool car_pose_ready;
是否至少成功收到过一帧位姿。
5、bool car_pose_updated;
是否刚收到一帧新位姿。
处理完后同样建议应用层手动清零。
6、uint8_t map_frame_count;
成功解析的地图帧数量。
7、uint8_t car_frame_count;
成功解析的位姿帧数量。
8、bool uart_rx_overflow_flag;
接收 FIFO 溢出标志。
如果它变成 true，说明中断进来的数据太快，FIFO 没塞进去。
