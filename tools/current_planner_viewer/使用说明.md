# 当前路径规划展示程序使用说明

## 1. 这个程序有什么作用

这个程序用于在电脑上直接运行项目当前的路径规划代码，并把每张预设地图的规划结果生成成一个可以用浏览器查看的 HTML 网页。

程序直接使用项目中的以下实际代码：

- `Algorithm.c`
- `Game_logic.c`
- `path.c`
- `Map_Path_Data.c`

因此，它展示的不是另外编写的模拟算法，而是当前项目算法在电脑上的规划结果。

程序会分别展示：

1. 识别阶段路径；
2. 推箱阶段路径；
3. 原始规划路径点数；
4. 提取后的实际执行路径点数；
5. 路径距离；
6. 规划耗时和路径提取耗时；
7. 识别、推物开始、推物结束、炸弹爆炸等事件点。

识别和推箱不是两次互不相关的模拟。程序会保留识别阶段结束后的车辆位置、已炸毁墙体和剩余炸弹状态，推箱阶段的第一个路径点必须与识别阶段的最后一个路径点相同。

这个程序只在电脑上运行，不需要连接 RT1064 核心板或 DAP 下载器，也不会控制小车运动。

## 3. 最简单的使用方法：展示全部地图

### 第一步：打开项目根目录

使用 Windows 资源管理器进入：

```text
D:\workwork\ASC _AIVision_Group2
```

### 第二步：在该目录打开 PowerShell

点击资源管理器顶部的地址栏，输入：

```text
powershell
```

按回车后，会打开一个 PowerShell 窗口。

窗口中的当前路径应该是：

```text
D:\workwork\ASC _AIVision_Group2
```

### 第三步：运行展示程序

在 PowerShell 中复制并执行：

```powershell
powershell -ExecutionPolicy Bypass -File tools\current_planner_viewer\run.ps1
```

脚本会自动：

1. 调用 GCC 编译展示程序；
2. 加载 map0 到 map8；
3. 对每张地图运行识别路径规划；
4. 对每张地图运行推箱路径规划；
5. 调用项目中的 `path.c` 提取实际执行路径点；
6. 生成 HTML 路径报告。

运行成功时，PowerShell 会显示类似下面的内容：

```text
map0: identify raw=10 exec=4, push raw=30 exec=11
map1: identify raw=10 exec=4, push raw=30 exec=11
...
map8: identify raw=21 exec=13, push raw=81 exec=47
HTML 路径报告已生成: ...\.tmp\current_planner_paths.html
```

如果地图结果后面没有显示 `[FAILED]`，表示该地图的规划和执行路径提取成功。

## 5. 只展示一张地图

使用 `--map` 参数可以只运行指定地图。

例如，只查看 map3：

```powershell
powershell -ExecutionPolicy Bypass -File tools\current_planner_viewer\run.ps1 --map 3
```

只查看 map7：

```powershell
powershell -ExecutionPolicy Bypass -File tools\current_planner_viewer\run.ps1 --map 7
```

只查看 map8：

```powershell
powershell -ExecutionPolicy Bypass -File tools\current_planner_viewer\run.ps1 --map 8
```

地图编号范围为：

```text
0 到 8
```

不写 `--map` 参数时，程序会运行全部预设地图。

## 6. 如何看懂网页中的路径图

每张地图包含两个图：

### 识别阶段

表示小车在正式推箱前，为识别箱子和目标点而行驶的路径，其中也可能包含识别阶段的炸弹处理。

### 推箱阶段

表示识别完成后，小车从识别路径终点继续执行炸墙、推箱、送达目标点和返场的路径。推箱图中的绿色小车位置应当与识别图中蓝色路径的最后一点一致。

### 图形和颜色含义

- 蓝色线：经过 `path.c` 提取后，实际准备交给小车执行的路径；
- 绿色三角形：小车出发位置；
- 棕色方块：箱子；
- 紫色圆圈：目标点；
- 黑色、红边圆圈：炸弹；
- 深灰色格子：墙；
- 橙色事件点：识别；
- 青色事件点：开始推动箱子或炸弹；
- 绿色事件点：结束推动；
- 红色事件点：炸弹爆炸。

事件点旁边的小数字是该点在实际执行路径中的序号。

### 查看完整路径点

点击每个路径图下面的：

```text
按执行顺序查看路径点
```

即可展开完整路径，例如：

```text
(5,0) — 移动
(5,4) — 识别
(4,8) — 识别
```

坐标格式为：

```text
(行, 列)
```

## 7. 页面中的数据是什么意思

每个路径图上方会显示类似：

```text
起点 (5,0) → 终点 (9,7) · 原始点 24 · 执行点 12 · 距离 31.42 格 · 规划 2.000 ms · 路径提取 0.000 ms
```

含义如下：

- 原始点：`Game_logic` 和 `Algorithm` 生成的连续栅格路径点数；
- 起点、终点：该阶段实际执行路径的首尾坐标；推箱阶段起点应与识别阶段终点一致；
- 执行点：经过 `path.c` 拐点提取和安全捷径处理后的路径点数；
- 距离：执行路径各线段长度之和，单位为地图格；
- 规划：电脑执行路径规划所花费的时间；
- 路径提取：电脑将原始路径转换成执行路径所花费的时间。

这里显示的是电脑端耗时，不等于 RT1064 板上的实际规划耗时。板端耗时需要使用板端基准测试程序测量。

## 8. 修改算法后重新生成结果

修改以下代码后：

```text
project\code\Algorithm.c
project\code\Game_logic.c
project\code\path.c
project\code\Map_Path_Data.c
```

重新运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools\current_planner_viewer\run.ps1
```

脚本会重新编译并覆盖旧的：

```text
.tmp\current_planner_paths.html
```

如果浏览器仍然显示旧结果，按：

```text
Ctrl + F5
```

强制刷新网页。

## 9. 检查 GCC 是否可用

脚本使用 GCC 编译电脑端程序。

在 PowerShell 中执行：

```powershell
gcc --version
```

如果能够显示 GCC 版本信息，就可以正常使用展示程序。

如果提示：

```text
gcc 不是内部或外部命令
```

说明 GCC 没有安装，或者 GCC 所在目录没有加入系统的 `PATH` 环境变量。

当前开发电脑已经成功运行过本程序，通常不需要重新安装 GCC。

## 10. 常见问题

### PowerShell 不允许执行脚本

请使用说明中的完整命令：

```powershell
powershell -ExecutionPolicy Bypass -File tools\current_planner_viewer\run.ps1
```

其中 `-ExecutionPolicy Bypass` 只对本次 PowerShell 调用生效，不会永久修改系统策略。

### 提示地图编号越界

`--map` 后只能使用 0 到 8，例如：

```powershell
powershell -ExecutionPolicy Bypass -File tools\current_planner_viewer\run.ps1 --map 3
```

### 出现 `[FAILED]`

表示该地图出现以下情况之一：

- 当前算法没有生成有效规划路径；
- 原始路径点不足；
- `path.c` 无法安全提取执行路径。

此时应查看对应地图以及算法修改内容，而不是只刷新网页。

### 网页无法打开

确认文件是否存在：

```text
D:\workwork\ASC _AIVision_Group2\.tmp\current_planner_paths.html
```

如果不存在，重新运行 `run.ps1` 并检查 PowerShell 中的错误信息。
